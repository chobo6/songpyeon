# 아이템 시스템(효과 로직) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 시간추가/시간감소/반죽공격/슈퍼절구 네 아이템의 발동 효과를 `useItem` Colyseus 메시지로 구현한다. 획득/보유 개수 관리는 범위 밖 — 팀이 네 아이템을 전부 무제한 보유했다고 가정하고 효과만 정확히 동작시킨다.

**Architecture:** 순수 계산(`ItemUseTracker`, `applyDoughAttack`, `applyTimeReduce`)은 `server/src/game/items.ts`에 분리해 vitest로 단위 테스트한다. 실제 Colyseus 타이머 재예약, `MatchState` 조작, 메시지 라우팅은 `server/src/rooms/MatchRoom.ts`에서 처리하고 `@colyseus/testing` 통합 테스트로 검증한다. 자세한 설계 근거는 `docs/superpowers/specs/2026-07-24-items-design.md` 참고.

**Tech Stack:** TypeScript, Colyseus 0.16(`@colyseus/schema`, `colyseus`의 `Delayed` 타이머 핸들), vitest, `@colyseus/testing` + `colyseus.js`(기존 `MatchRoom.test.ts` 컨벤션).

## Global Constraints

- 아이템 획득/보유 개수 관리 없음 — `useItem` 메시지가 오면 무조건 "이미 가진 것"으로 취급.
- **턴당 아이템별 1회만 유효** — 같은 아이템을 같은 창(턴) 안에서 여러 번 써도 효과는 중첩되지 않고, 이미 쓴 아이템의 재사용 메시지는 조용히 무시(에러 응답 없음).
- 네 아이템 모두 **자기 팀이 현재 턴을 잡고 있을 때만**(`activeTeam` 소속) 사용 가능. `phase !== "playing"`, 관전자, 턴 안 잡은 팀, `turnDecided === true` 상태에서는 전부 무시.
- **시간추가**: 사용 즉시 내 팀의 **현재 턴** 제한시간 +1초. 화면 표시(`turnEndsAt`)뿐 아니라 실제 서버 타이머도 재예약해야 한다.
- **시간감소**: 사용 시점이 아니라 **다음으로 시작되는 턴**(다음 `startTurn()` 호출 1회)의 제한시간 -1초, 최소 1초 보장(바닥 밑으로 안 내려감).
- **반죽공격**: 마찬가지로 다음 `startTurn()`에서 시퀀스 맨 앞에 민트 6개(1줄)를 붙임(길이 +6). 제한시간은 그대로.
- **슈퍼절구**: 사용한 팀의 **이번 턴 동안** 버튼 색상/역할 검증을 건너뛰고 어떤 버튼을 눌러도 정답 처리(커서 1칸 전진 + 콤보 증가는 정상 케이스와 동일).
- 시간감소와 반죽공격은 서로 다른 아이템이므로 동시에 걸어둘 수 있다.
- `MatchState`에 새 `@type` 동기화 필드는 추가하지 않는다 — 전부 `MatchRoom`의 private 필드로 충분(클라이언트 UI는 범위 밖).
- 재대결(`handleRematch`) 시 아이템 관련 트래커도 명시적으로 리셋해서 다음 매치로 새지 않게 한다.

```ts
import type { Color } from "./colors";
import { mintRun } from "./fragments";

export type ItemId = "timeAdd" | "timeReduce" | "doughAttack" | "superMortar";

const MIN_TURN_DURATION_MS = 1000;

// 같은 창(턴) 안에서 아이템별 1회 사용만 허용하는 최소 단위 — "이번 턴에 이미 쓴 아이템"과
// "다음 턴에 예약된 아이템" 두 군데 모두에서 재사용한다(둘 다 "한 번 쓰면 그걸로 끝, 또 써도
// no-op" 규칙이 동일하므로).
export class ItemUseTracker {
  private used = new Set<ItemId>();

  // 처음 쓰는 아이템이면 true(효과를 적용해야 함), 이미 쓴 아이템이면 false(무시).
  tryUse(itemId: ItemId): boolean {
    if (this.used.has(itemId)) return false;
    this.used.add(itemId);
    return true;
  }

  // 소비하지 않고 "예약/사용됐는지"만 확인 — startTurn()이 pendingItemsForNextTurn을
  // 조회할 때 씀(조회 시점에 지워버리면 doughAttack/timeReduce를 순서대로 두 번
  // 조회하는 도중 상태가 바뀌어버림).
  has(itemId: ItemId): boolean {
    return this.used.has(itemId);
  }

  reset(): void {
    this.used.clear();
  }
}

// 반죽공격: 시퀀스 맨 앞에 민트 6개(1줄)를 붙인다. 원본 배열은 건드리지 않음.
export function applyDoughAttack(sequence: Color[]): Color[] {
  return [...mintRun(6), ...sequence];
}

// 시간감소: durationMs에서 1초를 빼되 MIN_TURN_DURATION_MS 밑으로는 안 내려간다.
// 바닥을 두는 이유: turnDurationMs가 테스트에서 아주 짧게(예: 500ms) 설정될 수 있어,
// 그대로 1초를 빼면 음수/0 타이머가 되어 즉시 만료되거나 setTimeout이 오작동할 수 있음.
export function applyTimeReduce(durationMs: number): number {
  return Math.max(MIN_TURN_DURATION_MS, durationMs - 1000);
}
```
